One campaign only, maximum 90 s including intervals. Controller and PG have combined active caps of 256 MiB in the second workload. Use concurrency 1, no published ports and network none. PostgreSQL access is restricted to the host harness and disposable DB. Use existing 3 s inspect/list, 5 s create and 12 s attach budgets where applicable, clipped to remaining workload time. PG readiness uses its existing tighter 5 s start budget. Stop and removal share the existing 10 s cleanup budget. The plan keeps the 768 MiB MemAvailable and 4 GiB disk thresholds. Raw evidence should be bounded to 1 MiB for sampled records. At most 360 samples per stream, fixed numeric field schemas and no raw command output.

## Preflight, stop and cleanup

Review the instrumented runner and sample parser before owner authorization. Verify exact HEAD, both installed image IDs, recorded daemon ID through its local Unix socket, ARM64 and engine versions, ext4 identity, root-owned lab directory, prior evidence hashes including accepted E4a, and prior ledger absence. Reject stale or missing metrics. No pull or build. If the first workload cannot fit its budget, record BLOCKED and stop the campaign.

The independent watchdog samples host watermarks and checks daemon identity, deadline, process/container identity and write watermarks. Abort on memory/disk crossing their floors, OOM, resource-limit breach, missing critical samples, ambiguous ownership or changed inventory. Cleanup removes only the identified disposable writer containers after their work is stopped, verifies their IDs absent, then revalidates owned volumes and confirms no attachments before removing them. Retain resources if ownership or safe deletion is uncertain. Start no subsequent phase after any block. Keep a private ledger with run ID, labels, intended resource identities before creation, actual IDs/digests, ownership and cleanup attestations. Collect inspect observations without storing raw inspect, credentials or host source paths.

## Samples and acceptance

Use monotonic timestamps, phase labels, exact resources and explicit unavailable counters. Record host MemAvailable and disk free before/during/after. Track per-process RSS separately for PostgreSQL, controller, watchdog, host harness and Docker infrastructure by anchored PID and start time. Keep service-level RSS as context. Sample cgroup memory.current and memory.peak, memory.events, cpu.stat usage and throttling counters, io.stat deltas and pids.current alongside counts of observed processes. Track media/scratch bytes and PG directory growth without double-counting RSS and cgroup memory. Measure transaction/lock duration and create, start, stop and cleanup latencies individually. Store bounded call durations alongside SQL outcomes. If observed CPU throttling or clock resolution affects timing, report the limitation.

Pass requires both workloads within deadline, completed required sample streams, no OOM, all actual cgroup limits as declared, zero additional swap, lower host values at or above watermarks, unchanged retained hashes, and confirmed cleanup/inventory preservation. Otherwise report BLOCKED with the first violated condition and cleanup status. Report observed maximum usage, minimum host MemAvailable, minimum disk free and recovery delta. Compare the lowest measured host memory to the 768 MiB floor. Report the margin for the measured workload. This is not an estimate of how many additional processes or jobs are safe.

## Separate codec gate

Worker and verifier each have a project limit of 128 MiB, 0.75 CPU, 16 PID and an 8 MiB scratch budget, with zero extra swap. The four limits total 512 MiB. With PG and controller present and worker/verifier serialized, the configured active cap is 384 MiB. Neither is actual usage nor an OS reserve. E5A cannot establish codec headroom.

A future separate decision must fix the codec image digest, synthetic input and expected output hashes, and authorize any build, pull or WB workload explicitly. Proposed workload is one bounded decode and one verification sequentially, one controller slot, 30 s workload and 10 s cleanup per component under the same host floors, no mounts carrying real files, no networking or credentials. Apply the above measurement and block criteria. Keep both NOT_RUN until physically observed. No fault injection or power-loss test belongs to E5.

Owner gate for the next physical stage is OWNER_E5A_RUNTIME_APPROVED for one E5A campaign on a reviewed measurement-runner HEAD. This preparation supplies the runbook and offline acceptance checks.

Offline check: python3 -B -m unittest discover -s experiments/wb-lab-01 -p test_e5_plan.py. This checks host sample gaps, phase coverage, idle observation windows, watermarks and observed margins. The future runner must separately verify last sample freshness against phase closure and required process/cgroup streams.
