E1 implements the filesystem slice of VIS-CAT-02C (#52, #53 and #54) on the confirmed WB ext4 device. A single fresh, labeled local Docker volume contains only generated test files. Staging and final are separate directories on that volume. The existing pinned E0a controller image runs as UID 65532 with only loopback, no ports or credentials, and a read-only container root. Its single writable mount is the owned synthetic volume. The controller has 64 MiB memory, zero swap, 0.25 CPU and 16 PIDs. The existing 30 s workload deadline, 12 s attach budget, 10 s cleanup deadline, independent watchdog and 768 MiB RAM / 4 GiB disk watermarks apply.

Three sequential trials exercise successful promotion, exclusive-create collision and final-name collision. A successful promotion writes and syncs the file, syncs staging, creates the final link atomically with no replacement, syncs final, checks device, inode and SHA-256, then unlinks and syncs staging. Collision trials verify the original objects survive. An independent synthetic canary is verified after each trial. Unexpected errors stop the series. Offline faults cover write and file/stage/final fsync. Each file is limited to the fixed payload size and each trial uses fixed keys.

The output records step and trial timings, actual cgroup limits, peak RSS and cgroup memory, user/system CPU and cgroup I/O. The host checks the workload output, exit and watchdog, confirms writer absence, checks the exact owned volume and refuses cleanup on unexpected contents. PASS requires confirmed removal and preservation of pre-existing Docker inventory. The host keeps the private run ledger and evidence. WB ext4 results do not establish power-loss durability or VDS equivalence. E2–E5 remain NOT_RUN.

The approved one-shot entry point is `python3 -B experiments/wb-lab-01/runtime_e1.py OWNER_E1_RUNTIME_APPROVED`. It requires the pinned local image and the exact retained E0b evidence in the lab root. Subsequent execution is blocked by the presence of the E1 evidence directory.
