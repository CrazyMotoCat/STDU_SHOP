# VIS-CAT-02B laboratory benchmark

Review basis: [PR #37 at b7b29497ef519c952db0ed168de2a2f6cf2574f8](https://github.com/CrazyMotoCat/STDU_SHOP/pull/37). This is an experiment for Architecture A. Contract approval is a separate owner decision.

From the repository root, with Docker Desktop or an amd64 Linux Docker engine and Python 3.14:

```powershell
python -m pip download --only-binary=:all: --no-deps --platform manylinux_2_28_x86_64 --python-version 3.14 --implementation cp --abi cp314 pillow==12.2.0 --dest .local/vis-cat-02b-wheels
docker build --network none --platform linux/amd64 --build-context wheels=.local/vis-cat-02b-wheels --tag stdu-vis-cat-02b:offline-lab experiments/vis-cat-02b
python experiments/vis-cat-02b/run.py --image stdu-vis-cat-02b:offline-lab --output .local/vis-cat-02b-run.json
```

The wheel download is a dependency acquisition step. The build verifies its pinned digest, uses a pinned base image and disables network access for the install. The output path must be new. The driver creates disposable containers under unique names, with no ports, bind mounts or volumes. Each invocation has 1 CPU, 256 MiB RAM with swap disabled, 32 PIDs, 32 MiB tmpfs and a 30-second deadline. The tool runs one invocation at a time. Each decoder invocation gets only synthetic bytes over stdin. A verifier runs in a fresh container after the worker exits, with the same codec build.

The fixture generator creates RGB noise from recorded seeds and emits measured sizes and SHA-256 hashes. Fixtures are synthetic project test data. The driver records the digest of the actual over-cap sentinel separately where that sentinel replaces an oversized fixture. The default run takes two samples per fixture after one warm-up. Worker and verifier times measure the operation inside their respective processes. CPU and RSS are process measurements, and exclude container startup and the host driver. The scratch metric counts logical bytes remaining at the end of an operation. Codec paths are in-memory, and this metric does not establish peak disk use of a future staging pipeline.

The experiment uses 8 MiB per input, 5 million pixels, 2 MiB per rendition and 160/320/640/1200 maximum dimensions as lab inputs. The forced 1-byte rendition budget exercises rejection. These values are exploratory, and only the measured samples can support a subsequent resource experiment.

Before FROZEN, the owner needs to approve the target storage and recovery strategy, worker/verifier trust boundary and codec policy, rendition sizes and quality based on marking readability, measured per-job and aggregate capacity, rights and retention policy, and cache/revocation behavior. Public rendition delivery also needs a separate ADR-004 exception decision and approval of the R1-002/R1-004 amendments. The next lab stage can exercise the target filesystem and disposable DB intent fencing, then measure the worker and verifier under controlled concurrency.

## Recorded laboratory run

[Raw JSON results](results-lab.json) record Docker 29.8.0 on WSL2 Linux, Python 3.14.3, Pillow 12.2.0 and libwebp 1.6.0. Across 22 cases and two repetitions, 22 inputs were accepted and 22 rejected as expected. The verifier accepted all 22 sets of four renditions and rejected the deliberate digest mismatch. The largest rendition was 532,728 bytes. Both oversized PNG fixtures are recorded in the manifest, and the driver sends an explicit over-cap sentinel for each. JPEG and WebP at 2400 × 2200 exercised the pixel guard.

| Stage                  | Peak process RSS | Maximum process CPU | Maximum measured operation |
| ---------------------- | ---------------: | ------------------: | -------------------------: |
| Worker, all cases      |       86,964 KiB |             0.521 s |                 494.015 ms |
| Worker, accepted cases |       86,964 KiB |             0.521 s |                 381.283 ms |
| Verifier               |       54,152 KiB |             0.260 s |                  61.519 ms |

Scratch ended at zero for codec runs and the process block I/O counters remained at zero. The storage probe confirmed all six injected exits, exclusive stage creation, collision preservation and successful retry. The recorded tmpfs mount had `nosuid,nodev,noexec`. Read-only inspection of OPS-TEST-02 found a named volume at the API's `/data/files`, a shared backend network with PostgreSQL and loopback port mappings. That topology provides no evidence of worker egress denial. The benchmark ran in separate containers with no mount from OPS-TEST-02.

Keep the measured **1 CPU / 256 MiB / 32 PIDs / 32 MiB scratch / 30 seconds** envelope for the next bounded single-job experiment. It completed the observed workload with room above the measured process RSS, and the deadline includes container startup and transfer overhead. There was no limit sweep or concurrent workload. Peak process RSS cannot size a cgroup or a host on its own. Keep worker and verifier sequential until target-host measurements cover cgroup peak memory, contention and private staging.
