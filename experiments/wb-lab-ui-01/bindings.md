# SVG bindings

## Compatibility

The SVG editor's documented JSON mode exports and imports the binding description for a dashboard. The current upstream HomeUI source serializes this as a JSON array, with one object per SVG element `id`; an element can have `read`, `style`, or `visible` parameters. This task uses only `read` and `style`.

Read-only inspection confirmed `wb-mqtt-homeui` 2.267.7 on the target controller. Therefore **the JSON shape is confirmed against upstream HomeUI source, while import compatibility on this installed build is `NOT_VERIFIED`**; no import was attempted. Before upload, compare an export from the target's own editor after separate owner approval. Do not write directly to `/mnt/data/etc/wb-webui.conf`.

## File and mapping

[`bindings.json`](bindings.json) is generated by [`generate_dashboard.py`](generate_dashboard.py). Each `id` exists, unchanged, in both `dashboard-desktop.svg` and `dashboard-mobile.svg`, so the same JSON array can be imported into either panel.

All `read.channel` and `style.channel` values point at the documented WB control topic form:

```text
/devices/stdu_lab/controls/<Control>
```

The bindings use only:

- `read`: display a control value as text; progress and measurements append their documented units.
- `style`: map allowlisted status strings to fixed CSS fill colors. Status values are validated against the finite contract enum.

The JSON has no `write`, `click`, `long-press-write`, or dashboard navigation actions. There are no controls, buttons, or links in the SVG.

## Import in HomeUI

1. Open **Dashboards → List** and add a new SVG panel.
2. Set a unique panel ID such as `stdu-lab-desktop` or `stdu-lab-mobile`, and a readable name.
3. Upload the corresponding SVG file.
4. In the binding editor, choose **JSON view**, paste the contents of `bindings.json`, and save.
5. Use the editor's preview to check text, status colors, and the `DEMO · SYNTHETIC` mode badge. Confirm the displayed MQTT topic paths match this document.
6. Save the dashboard and use the documented fullscreen or HMI mode. Do not enable a command binding.

The SVG Dashboard documentation describes editing bindings in the HomeUI editor and saving/exporting them through JSON view. It also recommends separate mobile and desktop drawings when the screen size requires it. This repository package follows that flow; the actual controller import is pending owner approval.

## Expression note

The style expressions are ordinary JavaScript conditional expressions using HomeUI's documented `val` variable. The upstream renderer evaluates a binding expression against the selected MQTT value. The contract constrains every style input to known status enums; no log text or arbitrary value is returned as CSS.
