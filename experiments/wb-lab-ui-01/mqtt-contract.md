# `stdu_lab` MQTT contract

## Contract status

This is a proposed read-only telemetry contract for WB-LAB-UI-01. The HomeUI panel only subscribes to the listed value controls. The demo publisher can publish synthetic values to a broker when explicitly invoked; it never subscribes to command channels. All control metadata declares `readonly=1`. The JSON panel bindings contain only `read` and `style` actions.

Cold start remains `UNKNOWN` / `NO_DATA` / `NOT_RUN` with no measurements; in particular neither E0a PASS nor E0b BLOCKED seeds stage defaults.

## Topic and payload rules

- Device ID: `stdu_lab`.
- Device name: `STDU LAB · TEST TELEMETRY`.
- Control topic: `/devices/stdu_lab/controls/<Control>`.
- Control metadata: `/devices/stdu_lab/controls/<Control>/meta/{name,type,readonly,units,order}`. All channels publish `readonly=1` metadata. `type` is `text` or `value`.
- Payloads are short UTF-8 strings representing either an enum, UTC timestamp, or finite numeric value. No JSON object, secret, JWT, password, arbitrary log excerpt, or internal filesystem path is sent.
- All current values except `Heartbeat` are retained to make the last observation visible. `Heartbeat` is non-retained. Retained statuses such as `RUNNING` or `PASS` and retained metrics are last reported only; they do not prove a test is active or successful.
- The MQTT client uses a retained Last Will of `Collector_Status=OFFLINE`. On graceful shutdown it publishes the same state. Other retained controls, including `Telemetry_State`, remain unchanged. HomeUI cannot combine them into an effective freshness value, so the panel labels `Telemetry_State` as `LAST SAMPLE AGE` and separately shows the collector connection. `FRESH` means the last sample's age when published; with `Collector_Status=OFFLINE`, all retained values are last known and must not be read as current.
- Suggested LIVE cadence: resource and status snapshot every 5 seconds; heartbeat every 2 seconds. `Telemetry_State` records `STALE` when source age is greater than 15 seconds, and `NO_DATA` when there has never been a valid source snapshot. It is not a current-availability signal.
- The DEMO CLI uses a finite sample sequence (one second by default) solely to demonstrate updates and state transitions; it is not a service and not runtime evidence.
- The isolated local-broker transport procedure is [`DEMO-PLAN.md`](DEMO-PLAN.md). It never targets the WB broker and does not subscribe to or publish command channels.

## Controls

For the table, “demo” means [`demo-publisher.py`](demo-publisher.py) generates synthetic values only after explicit invocation. “Live source” states the required input class if one becomes available; none is wired in this task. Before an explicit DEMO or verified LIVE publication, the SVG remains at cold-start placeholders and the publisher does not emit default samples. After publication, values update on each snapshot and retain the last observation. The static `DEMO · SYNTHETIC` badge is not a HomeUI binding; the dynamic source mode is separate. The collector state and last-reported labels keep retained values from implying a current run.

## Offline and missing data

1. Before a valid snapshot, `Telemetry_State` is `NO_DATA`; measurements remain absent rather than substituting zero. The cold-start SVG uses `NO_DATA`, `UNKNOWN`, `NOT_RUN`, and em-dash placeholders and does not publish these defaults.
2. If a source timestamp is older than 15 seconds while the collector remains connected, publish `Telemetry_State=STALE` and retain it.
3. If the MQTT publisher disconnects, its Last Will marks `Collector_Status=OFFLINE`; other retained values are not cleared and can still include `Telemetry_State=FRESH`, `Status=RUNNING`, or stage `PASS`. These are last-known, last-reported values only. The panel labels the field `LAST SAMPLE AGE`, keeps collector state separate, and labels run/stage statuses as last reported. It does not show an aggregate `FRESH` status for an offline collector.
4. Unknown health, cleanup, or resource state is shown as `UNKNOWN`, never inferred as clear.
5. The explicitly started demo publisher shows `RUNNING → PASS` and `RUNNING → FAIL` with `Source_Mode=DEMO`. Its values are synthetic and retained as last reported; the static synthetic badge remains visible after MQTT text bindings are applied. These outcomes are not evidence for E0–E5.

## Security and resource limits

- The panel binds only to read channels and fixed status-to-color mappings. It has no write/click binding, no command topic, and no operator control.
- The bridge allowlists device/control names and status enums, limits text size, and rejects live frames until a verified source adapter exists.
- Never publish passwords, tokens, arbitrary log fragments, SQL, internal credentials, or private filesystem paths.
- Use low-rate snapshots and a non-retained heartbeat to limit broker history writes on eMMC. Do not configure high-frequency retained writes.
- No broker account, service, ACL, or controller file is created or changed by this task. A live MQTT account must be read-only from the collector's perspective and restricted to the `stdu_lab` namespace before any approved deployment.
