# B2B Graphite & Petrol — пакет технической постановки R1

**Статус:** базовая спецификация v0.1 для подготовки разработки; зафиксированы решения №1–108 и выбор R1.  
**Владелец продукта:** пользователь (оркестратор Codex).  
**Цель:** начать выпуск первой полезной версии, не строя преждевременно ERP/MES/SCADA.  
**Стек (утверждён):** Next.js, NestJS, Python/FastAPI, PostgreSQL, Redis, Docker, один российский VDS/VPS с внешними бэкапами.

## Читать в таком порядке

1. `01_DECISION_REGISTER.md` — полная трассировка 108 утверждённых решений; рядом `decision_registry.csv`.
2. `02_RELEASE_SCOPE.md` — **что именно входит/не входит в R1**, зависимости и критерий коммерческого запуска.
3. `03_MASTER_TZ_R1.md` — основное функциональное ТЗ на R1, роли, требования, критерии приёмки.
4. `04_ARCHITECTURE.md` — модульная архитектура и границы ответственности.
5. `05_DOMAIN_MODEL.md` — сущности, схемы состояний, правила неизменности и интерфейсы будущих релизов.
6. `06_API_CONTRACTS.md` — первичные контракты API и фоновые задачи; проектные наброски до генерации OpenAPI.
7. `07_SECURITY_OPERATIONS.md` — информационная безопасность, работа с файлами, развертывание и бэкапы.
8. `08_TESTS_AND_ACCEPTANCE.md` — критерии и проверки на уровне сценариев.
9. `09_ROADMAP_BACKLOG.md` — зависимые этапы и компактные задачи Codex.
10. `10_CODEX_ORCHESTRATION.md` — процесс работы пользователя и агентов, контроль изменений и интеграции.
11. `AGENTS.md`, `TASK_TEMPLATE.md`, `INITIAL_CODEX_PROMPT.md` — поместить в корень репозитория для Codex.
12. `11_DECISIONS_PENDING.md` — не более трёх вопросов, реально требующих определения перед полноценным запуском.

## Как использовать

Сначала закоммитить документацию. Один ведущий агент **не пишет все модули разом**: он создает монорепозиторий, фиксирует модель/контракты и небольшие интегрируемые вертикальные срезы. Каждая задача имеет DoD, проверяется тестами и только после этого считается принятой оркестратором.

**Внимание:** это технический проект и критерии реализации, а не свидетельство юридического соответствия, готовности к боевой эксплуатации или завершённая реализация. Веб/парсер и обработка загруженных документов требуют проверки применимых законов, условий правообладателей и безопасности до реального запуска.
