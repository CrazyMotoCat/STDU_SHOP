2. Apply that reviewed pattern to R1-006B/007B/010B without dropping runtime assertions or introducing blanket volume deletion.

4. Distinguish disposable smoke cleanup from retained operational stop; preserve existing environment data.
5. Add ledger/daemon/report and signal support to VIS-CAT-02B while retaining its tested cleanup deadline and negative cases.

For each change test only the affected lifecycle first: partial creation, success, timeout, signals, unavailable daemon, mismatched identity, retained resources, removal failure and non-running containers. Do not equate a green application suite with cleanup proof.

## Scope and safety compatibility

This inventory covers the four API Docker runtime entrypoints, R1-010C, shared smoke/ops connection paths and the merged VIS-CAT-02B runner. It is not a claim that every future or branch-only harness is compliant. WB-LAB-01 and OPS-TEST-02 are protected retained environments; no operation was attempted against either.

The policy changes only instructions and templates. It does not alter daemon settings, Compose files, CI workflows, toolchain, runtime code, FROZEN contracts, L0, upload/download security or required checks. Existing scripts remain runnable under existing gates; cleanup compliance must be stated separately until a runner's follow-up is verified. Policy activation requires the owner's decision and does not authorize resource deletion retroactively.
