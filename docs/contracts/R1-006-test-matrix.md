# R1-006B — контрактная и runtime матрица приемки

**Статус: PROPOSED вместе с контрактом R1-006 0.1.0-proposed.** Выполнение начинается только после фиксации владельцем схемы/API/RBAC.

| ID     | Сценарий                                                                                                     | Обязательное доказательство                                                                                                                                                                                     |
| ------ | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| IMP-01 | Additive migration на пустой и populated PostgreSQL                                                          | Новые таблицы/FK/indexes/checks применяются; R1-002/R1-004 fixtures, protected permissions, audit и catalog rows сохранены; destructive down не удаляет данные                                                  |
| IMP-02 | Upload доступен только authenticated staff с `catalog.products.read` + `catalog.products.write` + CSRF       | Anonymous -> 401, read-only или write-only -> 403; upload не создаёт product/revision                                                                                                                           |
| IMP-03 | Частный source FileObject/FileVersion                                                                        | SHA-256/size/MIME соответствуют байтам; storage key и FileVersion ID отсутствуют в ответах/логах; скачивания и public file route нет                                                                            |
| IMP-04 | Поддельный MIME/extension, oversized file, invalid ZIP, zip bomb bounds, macro-enabled XLSM и внешние ссылки | Отказ до создания FileObject/FileVersion/run; чужие volumes/objects не читаются                                                                                                                                 |
| IMP-05 | XLSX с несколькими листами, header row, пустыми строками и различным порядком колонок                        | Raw rows доступны до mapping; выбранный header становится HEADER, omitted sheet — IGNORED; лист и исходный номер строки сохраняются, допустимые строки доступны независимо от ошибки другой строки              |
| IMP-06 | CSV UTF-8/BOM, явно выбранный Windows-1251, неоднозначный delimiter, неизвестная кодировка                   | Поддерживаемые варианты читаются; неразрешённая кодировка/delimiter не угадывается и выдаёт явную ошибку                                                                                                        |
| IMP-07 | Text SKU с ведущими нулями и XLSX zero-mask integer                                                          | Значение сохранено без округления/потери нулей, второе помечено warning; неподдержанный numeric/formula SKU не принимается                                                                                      |
| IMP-08 | Formula, cached formula value, malformed row, oversized cell                                                 | Формула не вычисляется/не используется; только строка получает validation issue; остальные preview rows сохраняются                                                                                             |
| IMP-09 | Explicit column/reference/attribute mapping                                                                  | Неизвестный Brand/Category/AttributeDefinition не создаётся; AttributeDefinition применим только к exact categoryId; одинаковый code другой категории не наследуется                                            |
| IMP-10 | Exact identity and file-internal duplicates                                                                  | Только FROZEN tuple даёт EXACT_MATCH; title similarity не объединяет; missing key -> NO_DEDUP_KEY; duplicate-in-file явно видим                                                                                 |
| IMP-11 | Per-row ACCEPT_CREATE                                                                                        | Root + DRAFT revision создаются атомарно через catalog domain command; остальные rows неизменны; submit/pending/published pointer отсутствует                                                                   |
| IMP-12 | Per-row ACCEPT_REVISION                                                                                      | Используются существующий target и catalog OCC; новая revision DRAFT; submit/review/publish не вызываются                                                                                                       |
| IMP-13 | REJECT/HOLD и отсутствие массового принятия                                                                  | Одна команда меняет максимум одну строку; batch endpoint отсутствует; public product response неизменен                                                                                                         |
| IMP-14 | Concurrent catalog update/archive/submit after preview                                                       | Два PostgreSQL connections, блокирующее ожидание и final state подтверждают один допустимый исход; stale import конфликтует без overwrite/success audit                                                         |
| IMP-15 | Failure inserting success AuditEvent or ImportDecision                                                       | Транзакция откатывает import, product root/revision/pointers и decision; success audit отсутствует; ошибки не превращаются в success                                                                            |
| IMP-16 | Upload and row-decision retries                                                                              | Same idempotency key/body returns one saved result; changed bytes or CSV options with same upload key conflict; retry does not duplicate rows/products                                                          |
| IMP-17 | Partial parser response and preview resume                                                                   | Valid source rows and bounded sourceParseIssues persist as SOURCE_PARTIAL; preview retry uses saved raw rows, does not call parser again, duplicate rows, or rewrite decisions                                  |
| IMP-18 | Public and role boundary                                                                                     | Нет import API/DTO/source data на public routes; staff read/write используют frozen catalog permissions; permission registry не меняется                                                                        |
| IMP-19 | Exact FROZEN catalog regression                                                                              | Существующие CATB-01…38 и public catalog checks проходят без изменений                                                                                                                                          |
| IMP-20 | E2E-03                                                                                                       | Staff загружает CSV/XLSX, задаёт mapping, видит raw/normalized preview, решает строки отдельно; guest не видит unapproved changes                                                                               |
| IMP-21 | Raw source preview and mapping lifecycle                                                                     | До mapping staff API возвращает ограниченные исходные значения ячеек и координаты; выбор заголовка и исключённых листов меняет только candidate states; mapping можно исправить до первого APPLIED/REJECTED row |
| IMP-22 | Private FastAPI parser boundary                                                                              | Только private запрос Nest-to-ingestion вызывает parsing; NDJSON chunks/timeout ограничены; parser не имеет DB, Redis, storage, staff credentials или catalog command access                                    |
| IMP-23 | CSV options on initial upload                                                                                | UTF-8/BOM default, explicit Windows-1251, unique delimiter detection, explicit ambiguous delimiter, rejection of CSV options on XLSX; выбранные options и file bytes включены в upload idempotency hash         |

Required final evidence: disposable PostgreSQL runtime tests, API/HTTP auth/RBAC tests, representative CSV and multi-sheet XLSX fixtures, injected parser/audit failures, two-connection OCC test, UI/E2E-03, independent backend/database/security reviews, and exact-candidate GitHub CI. No production DB or deployment is in scope.
