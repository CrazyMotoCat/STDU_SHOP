## Исполнение и данные

Все test secrets случайные на запуск, только ephemeral fixture process/DB; fixture пароли не являются постоянными аккаунтами. Test DB отдельная tagged/случайно названная, не пользовательский volume; before/after sentinel snapshots. Роли/права fixtures используют коды из frozen matrix. Никаких prod, реальных банковских/налоговых реквизитов или внешних почтовых сервисов.

Lock/race evidence — barrier и подтверждённое ожидание PostgreSQL lock, затем commit/rollback/final DB state; Promise.all/timing сам по себе не доказывает атомарность. Критические auth/audit/migration сценарии не заменяются HTTP mocks. В A проверяется полнота этой матрицы и машинная согласованность артефактов, а не выполнение будущих тестов.
