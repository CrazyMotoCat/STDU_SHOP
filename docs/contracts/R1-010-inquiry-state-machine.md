# R1-010 Inquiry State Machine — PROPOSED 0.1.0

## States and transitions

```text
NEW -> TRIAGE
TRIAGE -> NEEDS_CLARIFICATION | ENGINEERING_REVIEW
NEEDS_CLARIFICATION -> TRIAGE | ENGINEERING_REVIEW
ENGINEERING_REVIEW -> NEEDS_CLARIFICATION | READY_FOR_QUOTE
READY_FOR_QUOTE -> NEEDS_CLARIFICATION | QUOTE_SENT
NEW | TRIAGE | NEEDS_CLARIFICATION | ENGINEERING_REVIEW | READY_FOR_QUOTE -> CLOSED (staff close without quote, required closure reason)
QUOTE_SENT -> CLOSED (later quote-lifecycle event only)
```

The sequence preserves REQ-02 and the domain model. The shorter branch from TRIAGE directly to ENGINEERING_REVIEW is explicit. Returning to TRIAGE means staff recorded that the requested clarification arrived. No new state is added: CLOSED is terminal for both closure paths. A typed `CloseInquiryWithoutQuoteRequest` is the only staff path to close an inquiry before quote delivery; it requires exactly one `reasonCode` from `DUPLICATE`, `CUSTOMER_WITHDRAWN`, `OUT_OF_SCOPE`, `SPAM` or `NOT_FEASIBLE`. Only a staff actor with `inquiries.transition` and current effective Inquiry read scope may close it. For an unassigned NEW inquiry, `inquiries.read_all` is necessary because assigned scope does not cover it. Eligible source states are NEW, TRIAGE, NEEDS_CLARIFICATION, ENGINEERING_REVIEW and READY_FOR_QUOTE. QUOTE_SENT is excluded from this command and can reach CLOSED only through the corresponding approved quote lifecycle. No path reopens CLOSED. The submitted request, contact snapshot, details, lines and source documents remain immutable; only state/version/stage deadline and the AuditEvent change. No quote or order is created.

Every staff command also requires an effective read scope and the action permission. Public actors have no transition endpoint. Frontend-hidden actions are not authorization. A successful close sets state to CLOSED, clears `stageDueAt`, increments version and writes `inquiry.closed_without_quote` with `AuditEvent.reasonCode` equal to the required closure reason. The state and audit are atomic; audit failure rolls the mutation back. CLOSED inquiries remain available to authorized staff in detail and event/history views, including an explicit CLOSED queue filter, but never through a public route.

## Assignment and concurrency

Manager and engineer assignments are separate PATCH commands and permissions. A target must be ACTIVE and have inquiries.read_assigned or inquiries.read_all. Commands assign or replace a target; clearing an assignment is not supported. Assignment changes do not change the Inquiry status. Every assignment command uses a strong If-Match version, a fresh staff/session/RBAC check, one PostgreSQL transaction and one AuditEvent. A stale version returns 409 VERSION_CONFLICT and changes no assignment or success audit.

Transition, pre-quote close, assignment and stage-deadline writers lock the Inquiry row, recheck current state and actor permissions after lock acquisition, apply the transition guard, increment version, insert the allowlisted audit event and persist the idempotency result in the same transaction. Two concurrent commands cannot both succeed from the same version. If-Match uses the same strong OCC version contract; stale or ineligible closure returns the existing safe conflict/validation error and produces no state change or success audit. A same-key/same-hash retry returns the exact saved receipt; a reused key with a different payload is rejected. Current session, CSRF/Origin, permission and read scope are revalidated before replay. A successful status transition, including either closure path, clears `stageDueAt`; staff may set or clear the deadline for the current stage through the separately audited stage-deadline command. `stageDueAt` is a human-set internal due date, distinct from a customer's optional `desiredDeadline`; R1 defines no automatic SLA calculation or notification.

Before looking up or returning a saved staff idempotency receipt, the API must revalidate the current session, CSRF/Origin, schema, effective action permission and inquiry read scope. A caller whose assignment/read scope was revoked cannot replay a receipt containing that Inquiry's identifiers. Public upload retries likewise revalidate the current unexpired inquiry-bound capability and intent binding before replay. A failed authorization check does not reveal the saved result. Public create retries need no inquiry-read authority because their response is only the original non-authorizing receipt.

Comments are append-only INTERNAL rows. Comment creation does not mutate the aggregate version; it requires inquiries.comment, inquiry read scope, CSRF/Origin and Idempotency-Key, and writes its row and audit atomically. Public messages are not supported. TransitionRequest has no free-text internalNote: reasonCode is the bounded audit reason, and any contextual staff note must be submitted separately through the comment command under inquiries.comment. Comments are not implicitly created by transitions.

## History

The existing R1-002 AuditEvent is the authoritative state/assignment/stage-deadline history, ordered by occurredAt then id. InquiryComment is the separate internal content store; AuditEvent records the comment event but never the comment body. State duration is derived from successful transition event timestamps. No parallel event-history store is added.
