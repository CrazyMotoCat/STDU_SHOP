## Уточнение OD-002A-02 по дополнительному ревью

Исходный HEAD e7807f60741785c1bc4b1c695d6542eb44c230e8 защищал только восемь control actions. Удаление чужого уникального sellers.write/audit.read при сохранении access-operator могло сделать восстановление через grant ceiling невозможным. Предложение уточнено: fixed fullAdminProtectedPermissions содержит ровно 12 первоначальных действий; пригодный сотрудник обязан иметь весь набор в собственном union ACTIVE ролей и готовые credentials. Все влияющие writers проверяют оба инварианта в одной READ COMMITTED транзакции под существующим advisory lock; обхода для привилегированного оператора нет. Безопасная owner-recovery ветка сохраняет readiness последнего full-admin, не выдаёт прав и не исправляет уже потерянный union. OD-002A-01 и 03…08 по существу не меняются; описание recovery синхронизировано с защитой OD-002A-02. Новые регрессии B: T-35…T-40. Весь пакет остаётся PROPOSED и требует принятия обновлённого HEAD.

## Версионирование

Все контрактные артефакты маркированы PROPOSED 0.1.0-proposed. До принятия изменения видны в PR diff и требуют повторного affected review/checks; owner принимает точный SHA. После FROZEN1.0.0 semantic breaking request/response/auth/permission/CSRF/DB invariants нельзя проводить как косметику: новый decision record, версия и явное согласование. API breaking — `/v2/staff` либо согласованный migration/deprecation plan. Новый permission всегда default deny; не расширяет автоматически старую роль. Additive изменение также проходит comparison/review и minor version, не скрытый drift. Параметры в согласованных безопасных конфигурационных пределах могут меняться оператором с аудитом/конфигурационной provenance; ослабление ниже floors требует отдельного security решения.

## Непроизводственные ограничения

Retention/PII, реальный домен/TLS/proxy allowlist, production secrets, реальные реквизиты, off-site backup/restore и VDS hash benchmark — не вымышлены и не объявлены готовыми. Для local B есть работающая конфигурация/тестовые ephemeral secrets; для production эти пункты — отдельная эксплуатационная приёмка. Они не требуют недостающего платного сервиса для реализации B и не разрешают production deployment.
