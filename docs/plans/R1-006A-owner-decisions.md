## Дополнительная фиксация API, конфликтов и ingestion protocol

- CSV encoding/delimiter фиксируются на upload и отсутствуют в `ImportMappingRequest`.
- Для `ACCEPT_CREATE` / `ACCEPT_REVISION` при каталожном или identity conflict каталожная попытка откатывается. Отдельная транзакция вместе фиксирует row `candidateState=CONFLICT`, одну `CatalogImportDecision.outcome=CONFLICT` с сохранённым точным 409 кодом и DENIED AuditEvent; API затем возвращает 409. Повтор того же ключа/hash возвращает сохранённый конфликт с тем же кодом без второй Decision/AuditEvent. Провал аудита откатывает conflict transaction и даёт 503; каталожного изменения нет.
- NestJS принимает только versioned UTF-8 NDJSON с LF-framed START/SHEET/ROW и одним terminal COMPLETE/PARTIAL record; transport chunks произвольны. Максимум 250 ROW и 4 MiB на logical batch, до 1 MiB на ROW. Поток без валидного терминала, с нарушением framing/order/schema или лимитов отклоняется целиком без FileObject/FileVersion/Run/Rows. Условия COMPLETE/PARTIAL и bounded parser errors описаны в контракте.

## Неизменяемые границы

- Все FROZEN R1-002A/R1-004A contracts и решения №1–108.
- Существующие identity tuple, product revision/state machine, publication flow и audit transaction rules.
- Не добавляются permission codes; frozen bootstrap/protected admin sets не меняются. Не добавляются сервисы, справочные записи или автоматическое создание справочников.
- Нет supplier import, quote-spec import, OCR/PDF, prices/stock, bulk acceptance, background schedules, production migration/deployment.
- До отдельной per-row staff command нет товара/ревизии; принятие создаёт/готовит только DRAFT; publication остаётся отдельным процессом R1-004B.
