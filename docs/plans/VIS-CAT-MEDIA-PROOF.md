## Подготовка и исполнение

1. **Зафиксировать входы.** Утвердить CD-01–04, перечень разрешённых фотографий, точный commit/image digest/codec build/DB/filesystem/mount/cgroup, разрешённый isolated host, интервалы и ресурсные пределы, условия остановки и bounded cleanup. До получения разрешений возможна только подготовка синтетических fixtures/mock-плана. Отдельно зафиксировать supported profiles, ожидаемые outcomes и правила PASS до измерений. Использовать отдельную disposable DB и один явным образом разрешённый media volume. Публикация только в локальном mock HTTP. Без стенда WB и production данных.
2. **Провести матрицу ниже по порядку.** Первый этап последовательно запускает offline worker и verifier без сети и использует доброкачественные искусственные изображения, malformed fixtures и контролируемые substitutions без живых вредоносных образцов. Нагрузку повышать от одиночного запроса и малой параллельности в пределах заранее утверждённого потолка. Реальные фото добавляются после проверки прав на fixtures, без выдачи за пределами стенда.
3. **Закрыть прогон.** Сохранить SHA-256 fixtures и файлов evidence, raw cgroup/latency samples, результаты SQL/digest, журнал отказов, график нагрузок и инвентарь до/после. Каждый результат содержит точный профиль и идентификатор прогона. Независимые Security/API/Data/Infra reviewers дают verdict по каждому условию. Missing или неидентифицируемое evidence оставляет условие NOT_PROVEN.
