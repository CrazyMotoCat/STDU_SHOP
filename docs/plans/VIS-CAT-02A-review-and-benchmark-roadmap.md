### Reproduction protocol

VIS-CAT-02B may implement one isolated benchmark harness; this plan itself does not run it. The harness must use a disposable database and private test volume in a non-production network, no host-published service ports, no production secrets/data, and synthetic or explicitly licensed fixtures with a checked-in manifest of source, license/basis, dimensions, expected digest and deterministic seed. Record OS/kernel, container/runtime versions, actual filesystem and mount options, CPU/RAM/disk limits, PostgreSQL settings, Node/codec/verifier builds, generator/load-tool versions, warm-up, run duration, repetitions and fixture manifest. Emit machine-readable raw results plus a short human summary; every value must be reproducible from the recorded profile.

Run the workload in three separate phases so results can identify the bottleneck:

1. **Ingestion/processing:** source sizes from ordinary to rejection fixtures; controlled single and concurrent attempts; measure source/output bytes, worker and verifier CPU/RSS, wall time, peak scratch space, disk reads/writes and retry behavior. Run worker and verifier sequentially as proposed; separately record peak RSS if runtime overlaps are tested.
2. **Public delivery:** use one product page workload requesting 50, 100 and 200 distinct images, each at the recorded fixed variant sizes, under low/medium/high concurrent clients. Separate cold storage from warm page-cache cases, and test GET, HEAD, matching 304 and revoked/unpublished 404. Compare full SHA-256 preverification on every request with the unapproved performance alternative (verification before READY plus a bounded integrity scrub); comparison does not authorize changing the security contract. Measure throughput, p50/p95/p99 latency, API/Next CPU and RSS, file descriptors, bytes read/written, disk IOPS/queue, connection-pool use, PostgreSQL query latency, row-lock wait and transaction duration.
3. **Races and recovery:** while delivery load runs, concurrently publish, unpublish, archive and revoke; record the snapshot result and verify the documented in-flight boundary. Inject malformed/truncated input, MIME/signature mismatch, worker/verifier timeout or kill, API restart, database outage, disk-full/quota exhaustion, crash before/after stage sync, after atomic promotion and before/after the fenced DB commit, stale lease writer, missing object and checksum mismatch. Restart and run bounded reconciliation; prove it neither deletes referenced bytes nor leaves committed pointers to missing bytes.

Use repeated runs with identical fixtures and configuration. Report raw samples and percentiles, CPU seconds, peak RSS, filesystem bytes/IOPS, PostgreSQL lock wait and pool saturation, error rates, and successful recovery. Label any run outside the intended VDS as **laboratory evidence** only; it cannot establish production sizing. No final numeric limits or cache TTL are selected until an independent infrastructure review and owner decision.

## Required acceptance evidence for later implementation

These are future gates, not checks that can pass on this documentation-only PR:

- DB constraint tests prove source/product/revision/set/derivative namespace binding and prevent cross-product or cross-generation attach.
- DB tests prove one source FileVersion cannot be claimed by two products; `(renditionSetId, variant)` is unique; all profile-required variants exist exactly once before READY; source and derivative FileObjects remain PRIVATE/eligible.
- Concurrent retry tests prove actor-scoped idempotency-key reservation converges for same-body requests and rejects changed body/target; storage intents prove lease fencing blocks stale-writer commits and cleanup, including a paused writer racing reconciliation, temporary-stage crash recovery, file/directory durability ordering on the selected target mount, and both transaction race orderings.
- Transaction/race tests prove OCC, publication, product archive, media revoke and product-match confirmation bound to the exact rendition-set/manifest. Public authorization uses one short MVCC snapshot with no row locks held during storage I/O: a snapshot after committed revoke/unpublish denies, while a request whose snapshot linearized first may finish. Race tests must demonstrate both outcomes and ensure every visibility transition is committed atomically.
- Worker adversarial tests prove exact job/digest/profile/policy binding, echoed single-use nonce consumption, replay/mismatch rejection, idempotent retry, changed-body conflict, stale output rejection, no secret/path/ID leakage, API-only ingress, denied egress, and bounded resource use. Malformed worker output is decoded only in a non-root isolated verifier with no network, host mounts, DB/storage authority, or unbounded IPC; the privileged API never runs the full image decoder.
- Storage crash/recovery tests prove intents survive process termination between DB reservation, physical write, FileVersion commit, derivative-set commit, and READY finalization; reconciliation only deletes exact expired unreferenced artifacts.
- API tests prove source/private FileVersions are inaccessible via generic routes; public route only serves verified WebP from PRIVATE/eligible FileObjects; safe uniform 404 versus dependency 503; 304 uses the same authorization snapshot and full-byte check; HEAD has no body; headers/digest/length are correct; proxy status/header mapping is exact; total/idle timeout and downstream cancellation abort upstream; pre-header byte verification occurs outside any database transaction and sends from the same verified immutable file handle; mid-stream failures abort without fallback.
- Quota tests prove concurrent upload/job caps, staging/retained-media high-water behavior, pre-reservation rejection at a hard cap, and no deletion of linked files to reclaim space.
- RBAC tests prove default deny, exact target-product checks, no automatic grant, no rights from file ownership alone, and unchanged generic R1-002 `files.metadata.read` behavior.
- Audit tests prove human provenance confirmations have exact staff/time; the proposed `SYSTEM` actor is absent from the current frozen registry, so future tests must prove null staff/operator identity, exact job/attempt correlation, finite action/value constraints, API-only emission, and no ProductRevision or file-delivery authority. Logs omit raw bytes, keys, original names, rights evidence and PII.
- Frontend tests prove card image can be absent, detail gallery is a static ordered accessible image list, alt text/dimensions and responsive rendering are correct, native `<picture>` uses explicit same-origin `srcSet`/`sizes` for fixed variants, and no arbitrary URL/Next optimizer cache proxy is created.
- OpenAPI/client compatibility is checked before any public response change. The checked-in V1 card/detail schemas are strict and have `additionalProperties: false`; the web wrapper and generated package are inventoried, but no external consumer registry exists. Therefore the current draft keeps V1 unchanged and proposes versioned V2 image responses; adding fields to V1 requires a separate compatibility proof and owner decision.
- Full review/benchmark and one exact-head CI run are required after runtime implementation. No check in this proposal substitutes for those gates.
