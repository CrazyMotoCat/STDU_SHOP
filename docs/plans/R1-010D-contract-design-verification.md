## Additional boundary and timing checks

A controlled API-compromise exercise must demonstrate that an API principal with direct snapshot read access can exfiltrate bytes through another permitted channel: this is a known **out-of-model residual risk**, not a test expected to PASS as prevented by the HTTP gate. Any attempt to protect against compromised API needs a separately approved trusted serving architecture. Test delayed transaction after obtaining locks across expiry; `clock_timestamp()` avoids stale transaction-start time but does not itself prove validity at commit; freeze remains blocked pending a precise approved rule. Test ordinary credential rotation keeps existing evidence valid, whereas incident revocation is explicitly audited and atomic under policy/document anchors. A per-download fallback copy is not the same object version and remains BLOCKED until an approved binding attestation exists.

**Scanner control adversarial test:** a compromised worker sends real clamd `RELOAD` and `SHUTDOWN` over its reachable scanner endpoint while verifier scans. Without independent daemon isolation or a proven command filter, this is a known failing boundary and CLEAN remains BLOCKED; the test is not claimed PASS. Demonstrate protected daemon identity, atomic signature epoch and reload exclusion under the selected owner-approved topology. Test CSV job profile is persisted before any bytes are parsed and that guessing/retry cannot change it.
