# R1-010D policy B: download authorization, revocation and DB privileges

**DRAFT / REVIEW_REQUIRED / NOT FROZEN — DESIGN_GATE_BLOCKED.** Every predicate term and lock is proposed; existing contracts remain frozen. OA-01 approves decision ordering, not implementation.

## Predicate and linearization

`allow = active_staff_session AND permissions(download,read) AND current_inquiry_scope AND document_in_inquiry AND safety=CLEAN AND original_snapshot_identity_matches_evidence AND policy_exact_version_active AND evidence_current_unrevoked AND eligibility_current_unrevoked AND protected_snapshot_ready AND audit_begin_commit`. Evidence includes exact document/key/version/digest/size, job/version/lease, profile and immutable issuer; evaluate expiry using database time. Unknown/expired/revoked/missing data, inconsistent projection, inaccessible snapshot/DB/audit => deny. Snapshot preparation may occur before DB commit but cannot expose bytes; recheck protected identity under authorization. Session and business scope retain existing semantics, including existing 401/403. Commit of authorization transaction is the linearization point, including durable begin audit; do not send headers before commit. Revoke commits first => auth sees revoked and denies; authorization commits first => that one protected stream can start/finish even if first byte follows revoke. Later authorization denies. HTTP bytes are not atomic with DB; abort after commit is separately auditable on a best-effort basis and never a claim of delivery completion.

## Existing SQL paths and candidate lock graph

PR #28 migration `apps/api/prisma/migrations/20261028120000_inquiry_scan_jobs/migration.sql`: claim locks job `FOR UPDATE SKIP LOCKED` then source (lines 251–253, 283–286); finalize job then source (412, 477); retry job then source (594–596), each writes audit within transaction. Read-authorized has its own path, no assumption of lock beyond implementation. Download in `inquiries.service.ts:1905` locks inquiry, verifies scope, reads source, opens file and writes audit; audit insertion is not evidence of an explicit audit-row lock order, and FK/index/trigger locks must be inspected. Finalizer does not currently issue eligibility. Cross-path staff/session/inquiry/assignment/audit FKs and trigger locks remain unverified.

Candidate partial order after existing auth locks: inquiry → job when needed → source → policy anchor sorted `(id,version)` → document eligibility anchor → evidence → append-only revoke/audit. Never acquire an earlier anchor after a later one; operations without inquiry must never later acquire inquiry, and order sorted IDs when multiple. All policy-revoke, evidence-revoke, eligibility-issue/revoke and authorization transactions lock the **same pre-existing stable policy/document anchor rows** in that order `FOR UPDATE` before checking or appending revocation; active-slot has a unique document key, FK to exact evidence and policy/version and is changed only through SECURITY DEFINER. Anchor creation/source upload ordering must be defined; missing anchor => deny, never insert opportunistically in download. At READ COMMITTED, re-read predicates in a new statement after obtaining locks, so a concurrent committed revoke cannot be hidden by a statement snapshot. Append-only revoke unique per target, and slot unique by document; expiry is checked at DB time, not a volatile `now()` partial index. Revoke does not require updating immutable evidence; slot removal and revocation insert+audit occur atomically. Policy disable locks its stable policy anchor first; if cascades would require backwards document locks, do not cascade: evaluate active policy under same anchor for each download; derive global graph and prove before freeze.

This is a candidate, **not a deadlock proof**. New SQL paths, FK enforcement, session/scope revocation and implicit locks may invert the graph. A real PostgreSQL lock graph / barriers and repeated two-connection tests for download↔revoke, claim↔finalize, finalize↔issue, policy revoke↔download, retry↔old lease, concurrent issue and replay are required. Deadlock/serialization error rolls back and denies; no unconditional retry that might extend authorization beyond expiry. Current exactly-four function contract must be amended before any additional function or role.

## Time and issuer coordination — mandatory gate

Verifier-only positive finalization is a single SECURITY DEFINER transaction: lock job → source → policy/document anchors; after locks read persisted evidence and issuer, exact source identity, job/version/lease hash and policy; use fresh `clock_timestamp()` after lock waits to test expiration; atomically transition source/job, insert eligibility/current slot and audit. Reject untrusted worker calls, mismatched canonical replay or expired evidence; worker retains only separately restricted non-CLEAN result path. A verifier-supplied asserted identity is never authoritative. This changes the exact-four-functions contract.

PostgreSQL `now()` and `transaction_timestamp()` are fixed at transaction start and cannot establish validity after waiting for a lock. Fresh `clock_timestamp()` is required after all locks for session, lease, policy and evidence expiry; however even that is not proof that the transaction committed before an expiry deadline. **DESIGN_GATE_BLOCKED:** owner/security/database must approve a precise expiry linearization rule and prove it under delay before commit, or explicitly adopt a checked-at-decision semantics and bounded transaction while describing its residual window. Do not claim strict validity at commit from a precommit clock read. Normal rotation does not revoke evidence; suspected issuer compromise uses an audited explicit policy/eligibility revoke under the same anchors.

## Non-executable schema and functions sketch

All IDs below UUID NOT NULL unless marked optional; `digest` is exactly 32-byte `bytea`, `size` positive bigint, all timestamps `timestamptz NOT NULL`. This sketch is not a migration; names, enum types, exact FK index strategy and PostgreSQL privilege ownership require a final owner-reviewed amendment.

- `PolicyVersion(policy_id, version integer > 0, profile_id text, active_from, expires_at, created_at, primary key(policy_id,version))`; immutable policy contents; monotonic revoke separate. Stable policy anchor keyed `(policy_id,version)` and unique version must exist before use.
- `CompletenessEvidence(id PK, document_id FK, object_version text, storage_key text, digest, size, job_id FK, job_version integer > 0, lease_hash bytea[32], policy_id, policy_version, profile_id text, validator_version text, scanner_image_digest text, signature_epoch text, start_at, end_at, expires_at, issuer_login text, correlation_id text)`. Composite FK `(policy_id,policy_version)` → policy, composite binding `(job_id,document_id)` → unique job pair; unique `(id,document_id,object_version,digest,size,policy_id,policy_version,profile_id)` for exact eligibility FK. Verify `start_at <= end_at < expires_at`, profile equality and exact current lease inside locked procedure; no evidence update/delete. No raw lease token.
- `DownloadEligibility(id PK, document_id FK, object_version, digest, size, evidence_id, policy_id, policy_version, profile_id, issued_at, audit_id FK)` with composite FK to the full evidence binding above and immutable row; unique `(id,document_id)` for slot. No UPDATE/DELETE.
- `EligibilityRevocation(id PK, target_kind enum, target_id, revoked_at, audit_id FK)` conceptual polymorphic shape must **not** be implemented without provable target FK: use typed nullable eligibility/evidence/policy FK columns with CHECK exactly one set (including policy id+version pair together), per-target unique partial indexes or separate typed tables. Append-only and immutable, no generic unchecked target UUID.
- `CurrentEligibilitySlot(document_id PK FK, eligibility_id NOT NULL UNIQUE, composite FK (eligibility_id,document_id) → eligibility)` projection mutable only within locked audited procedures; never relies on time-based partial index. Remove slot on eligibility revoke, read policy/evidence revoke separately under stable anchors; check expiry after lock, expiry itself does not silently mutate audit. One active slot at most per document.

Candidate typed operations: `verifier_read_binding(job_id,job_version,lease_proof)` verifier LOGIN, returns only exact binding; `verifier_record_evidence(job_id,job_version,lease_proof, measurements, canonical_request_id)` verifier LOGIN, authenticated issuer from session, immutable insert and audit; `verifier_finalize_and_issue(job_id,job_version,lease_proof,evidence_id, canonical_result_hash)` verifier LOGIN, locks/rechecks full chain and atomically changes source/job/slot/audit; `staff_authorize_download(inquiry_id,document_id, staff_session_context)` API LOGIN only, validates server-side session/scope and full chain, commits begin audit; `operator_revoke(target, reason, correlation)` operator LOGIN only, target-specific typed function preferable. Staff session context is untrusted until independently validated against persisted session/actor, and issuer is never a parameter. Signatures are illustrative, not approved; exact replay equality must include authenticated principal and all canonical identity dimensions. Direct table writes and worker calls to the positive functions are forbidden.
