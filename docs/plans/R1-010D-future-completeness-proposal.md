# R1-010D — proposal: future scan completeness policy

Status: PROPOSED FOR OWNER DECISION. This is not an amendment and does not enable CLEAN. The worker and database denial remain in force.

## Common preconditions

A future design must identify the actual bytes with a strict bounded parser, reject type/extension mismatch and ambiguous or polyglot inputs, enforce stream/expanded-size, nesting, object-count and time budgets, verify exact bytes and scanner attestation, and record a verifiable completeness result before both worker and SQL may allow CLEAN. A claimed MIME, extension, source SHA-256 or `stream: OK` alone is insufficient. Any unsupported, encrypted, truncated, ambiguous, resource-limited or incompletely parsed input stays unavailable. Scanner upgrades require separately approved, digest-pinned evaluation; malware analysis is not replaced with a custom antivirus.

| Class | Candidate eligible profile, subject to separate review                                                                                                                                                                                                       | Evidence and unresolved questions                                                                                                                                                                                                                                        |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CSV   | Strict UTF-8 text with bounded rows, columns and cell lengths, no binary data, no embedded container or polyglot. Decide BOM and permitted control bytes explicitly.                                                                                         | Validate the entire stream and test disguised ZIP/PDF, malformed UTF-8, hostile formula text, boundary lengths and EICAR at various positions. Prove scanner behavior including PCRE before enabling any profile; CSV validation does not sanitize spreadsheet formulas. |
| PDF   | A specifically approved bounded PDF subset with independently validated cross-reference graph, decompressed streams and object count/depth; reject encryption, unsupported objects, attachments and ambiguous incremental updates unless explicitly covered. | Test actual embedded files, compressed streams, malformed cross-references, polyglots, nested objects, encrypted inputs, scanner limits and EICAR controls. The suitability and safe bounded parser for the subset are not established.                                  |
| XLSX  | A strictly validated OOXML package, complete ZIP structure, CRC, sizes, relationships, supported content types and bounded expansion; reject encrypted, unsupported, orphan or embedded parts unless specifically proven covered.                            | Test valid normal Excel workbooks and embedded objects with independent ZIP/OOXML tools; prove exact byte access, limit signals, EICAR and resource/timeout handling on the exact scanner. Current valid worksheet EICAR returned OK; XLSX CLEAN is not supported.       |

Each profile requires explicit ceilings for original and expanded bytes, recursion, file count, CPU, memory, scratch and time and evidence under pinned engine/signature configuration. Every boundary and unsupported class must be tested through private storage, worker, DB finalize, audit, replay/fencing and download authorization. A decision must specify how a trustworthy per-scan completeness attestation reaches and is independently enforced by the database; a worker-only boolean is insufficient. Enablement requires a versioned security contract amendment, independently reviewed worker and database migration, a safe operational rollout and owner approval. Keep default deny for all new or unrecognized formats.

None of these candidates establishes a guarantee that a file is malware-free; practical parser choices, deployment capacity, signature coverage and all legacy CLEAN remediation remain separate open decisions.
